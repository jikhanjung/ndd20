# DB 기반 크롭 최종 검토

사용자가 자동 문턱에 의한 선별보다 이미지 검토를 우선하고, 원래 폴리라인,
모델 마스크·밑동, AI 관찰을 함께 보면서 사람이 최종 판단하도록 요청했다.
관련 정보를 모두 DB에 저장하라는 명시적 요청에 따라 이전 보기 전용 및
localStorage 계획을 대체했다. 형제 저장소와 그 DB는 건드리지 않았다.

- `/`: 판·개체·최종 판정·AI 검토 여부를 필터링하는 목록. 기본은 ID가 있는 영역.
- `/review/<pk>`: 고해상도 크롭 원영상과 오버레이 비교, 원본 전체 보기,
  AI 관찰 범위/불확실성, 사람의 최종 판정과 원영상·마스크·밑동 상태 및 메모.
- `/browse`: 기존 자료 탐색.
- `Run`과 `CropReview`는 출처 및 라벨/추론 JSON 전체를 보관한다. 입력과
  라벨의 합성 해시로 가져온 판을 식별한다. 같은 판을 다시 가져와도 사람이
  남긴 판정을 덮어쓰지 않는다.
- `ReviewHistory`에 매번 판정 스냅샷을 남긴다. 버전 비교와 트랜잭션으로
  오래된 화면의 저장을 거절하고, CSRF 검사를 활성화했다.
- 로그인은 추가하지 않았다. 판정자 이름은 직접 입력한다. 좌표 수정은
  구현하지 않았으며 수정 필요 상태와 메모를 저장한다.

독립 `review.sqlite3`에 GPU 결과 2,939개, ID 있는 영역 424개를 가져왔다.
실제로 크롭 원영상을 확인한 6개에만 AI 관찰을 가져왔다. 오버레이까지
검토했다고 표시하지 않았고, 사람의 최종 판정은 한 건도 자동 생성하지 않았다.

검증: Django 시스템 검사 및 마이그레이션 일치 확인, 테스트 6개 통과
(저장/이력/충돌, 입력 검증, CSRF, 목록 필터, 저장 후 다음, 재가져오기 보존).
실제 DB로 목록·상세·이미지·기존 탐색의 HTTP 200 응답도 확인했다.
브라우저 렌더링의 육안 검사는 수행하지 못했다.
